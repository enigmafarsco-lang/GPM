# GPM FPGA Package — Verilog implementation for the AMD RFSoC ZCU208

Synthesizable RTL port of the validated MATLAB/Simulink GPR signal chain
(`gpr_pipeline_spec.m`, package v1.8) targeting the **ZCU208 evaluation kit**
(**XCZU48DR-2FSVG1517E**: 8× 14-bit 5 GSPS RF-ADC, 8× 14-bit 10 GSPS RF-DAC,
4272 DSP slices, 60.5 Mb on-chip memory, 4 GB PL-DDR4).

Every stage of the algorithmic chain — tone generation, coherent averaging,
calibration, windowed IFFT range compression, background removal, Kirchhoff
migration, CA/log-CFAR detection and clustering/reporting — is implemented in
plain Verilog-2005 and verified **bit-accurately against golden vectors
generated by the MATLAB/Octave reference model**.

```
fpga/
├── rtl/        14 synthesizable modules (the deliverable)
├── tb/         9 self-checking Icarus Verilog testbenches
├── sim/        debug harnesses + small-parameter TB ROMs (*_t.hex)
├── golden/     make_golden.m + all golden vectors / ROM images
├── scripts/    run_sims.sh (full regression), vivado_build.tcl (ZCU208 build)
├── xdc/        zcu208.xdc timing/board constraints
└── reports/    generated utilisation/timing reports (after vivado_build.tcl)
```

## 2. Architecture

```
                    ┌────────────────────────────── gpr_top_zcu208 ──────────────────────────────┐
 PS M_AXI_HPM0_FPD  │                                                                            │
 ──► AXI-Lite regs ─┼─► config/ROM words to every block                     irq ──► PS (EMIO)    │
                    │                                                                            │
  DDS (gpr_dds_txc) │  fw/amp/tidx/sb ROMs, dwell counter, sub-band handshake sb_req/sb_ack      │
   │  m_axis_dac ───┼──► RFDC DAC tile (interpolation + fine NCO)                                │
   │  loopback mux  │                                                                            │
   ▼                │                                                                            │
  adc_if (AGC Q14) ► avg (2^LOG2NAV coherent sweeps/tone) ► cal (H_sys⁻¹ ROM) ► window (Kaiser)  │
   ► fft (radix-2 DIT, 16→2048 zero-pad, /2 per stage + gain_q10)                                │
   ► background (median of nbg positions, ping-pong RAMs, insertion sort)                        │
   ► migrate (Kirchhoff: Q20 fb geometry, CORDIC magnitude, exp-LUT absorption, raised-cos       │
   │          aperture taper, coherent phase, 64-bit MAC, out_scale_q8)                          │
   ► cfar (frame RAM, p_floor, separable rolling box sums — big window 25×25, guard 9×9,         │
   │       dual-chain A−B guard alignment, clipped-edge valid counts, mean/log mode,             │
   │       two output passes: det flags + re-stream)                                             │
   └► cluster (two-pass union-find on detection labels, report registers REP1..REP6, rep_done)   │
                    └────────────────────────────────────────────────────────────────────────────┘
```

All data interfaces are AXI4-Stream, `tdata[31:0] = {I[31:16], Q[15:0]}`
signed Q15, `tuser_tone`/`tuser_pos` 8-bit, `tlast` = end of sweep / row.
The whole chain is **single-clock** (F_CLK = 245.76 MHz nominal), with
`tvalid/tready` backpressure honoured end-to-end.

Shared arithmetic primitives: `cordic.v` (mode 0 rotate / mode 1 vectoring,
Q0.32 turns, K_Q24 = 10188014 both directions, 24-entry atan LUT) and
`gpr_div.v` (u32/u16 restoring, 33 cycles, start/done pulse interface).

### Module notes

| Module | Highlights |
|---|---|
| `gpr_dds_txc` | phase-accumulator + CORDIC sine; per-tone amplitude ROM (baked B02/B03 chain: predriver, PA soft compression, cable loss); `N_POS` parameter stops cleanly after one frame; sub-band-major tone order with `sb_req/sb_ack` PS retune handshake |
| `gpr_adc_if` | AGC multiply, Q14 gain |
| `gpr_avg` | per-true-tone accumulator RAM, n_avg = 2^LOG2NAV sweeps, saturating flush with rounding |
| `gpr_cal` | per-tone complex divide by H_sys ROM (Q14), |H| floor 1e-9 mirrored |
| `gpr_window` | Kaiser window ROM multiply |
| `gpr_fft` | radix-2 DIT, bit-reversed load, `>>1` per stage rounding, output gain_q10; load/zero/start/output FSM with hold-until-accepted final beat |
| `gpr_background` | rolling median over nbg positions per bin (insertion sort, re-armed outer index), ping-pong frame RAMs, `bg_overrun` status |
| `gpr_migrate` | Q20 geometry (fb/roff/dx/dr), Newton sqrt (7 iter), reciprocal via `gpr_div`, exp-LUT absorption (1024 entries), CORDIC magnitude, raised-cosine aperture taper, coherent exp(+j2β₀R), 64-bit MAC → Q15 sat26, row 0 emitted as zeros |
| `gpr_cfar` | frame RAM capture, p_floor = max·2874>>28, separable rolling sums: big 25×25 and guard 9×9 (guard center-aligned via dual chains A−B, BGA = W+G+1 / BGB = W−G slots), valid-count popcount windows with clipped edges, mean mode `p·cnt·4096 > α_q12·(sum−gsum)` and log mode with icrom reciprocal LUT + γ/α Q26 terms; two output passes with per-row `tlast` and per-frame `frame_last` |
| `gpr_cluster` | label RAM union-find with merge resolution, per-label peak/centroid stats, REP registers, `rep_done` pulse |
| `gpr_axil_regs` | full register file (below), W1C IRQ, beat counters |

> **Verilog portability note:** all multi-field RAM addresses are built with
> concatenation `{slot, col}`, never shift-or — a shift inside an index
> expression is self-determined to the operand width in Verilog and silently
> aliases addresses (this was a real bug found in simulation).

## 3. Register map (AXI4-Lite, 32-bit, offset = byte address)

| Offset | Name | Description |
|---|---|---|
| 0x00 | ID | `0x47505218` ("GPR" + ver 1.8) |
| 0x04 | CTRL | bit0 `run` (one-shot frame), bit1 `loop_mode` |
| 0x08 | STATUS | bit1 `irq_ev`, bits[23:8] `frame_count`, bit24 `bg_overrun` |
| 0x0C | IRQ | bit0 `irq_ev` (W1C), bit1 `irq_en` |
| 0x10 | DWELL_CYC | fabric clocks per tone (mode A @245.76 MHz, 50 µs → 12288) |
| 0x14 | NAVG_M1 | n_avg − 1 (mode A: 31) |
| 0x18 | AGC_Q14 | adc_if gain |
| 0x1C | FFTGAIN_Q10 | FFT output gain (mode A: 18872) |
| 0x20 | NBG | background median window (positions) |
| 0x24–0x30 | INV_DR_Q20, ROFF_Q20, DX_Q20, DR_Q20 | migration geometry |
| 0x34 | KBETA_Q16 | Kaiser/migration β |
| 0x38 | ALPHA2_Q8 | absorption slope (signed) |
| 0x3C | MAXBIN[15:0], OUT_SCALE_Q8[31:16] | |
| 0x44/0x48 | B_MIN0 / B_MAX0 | CFAR valid depth band (rows) |
| 0x4C | CFAR_MODE | 0 = mean (mode A), 1 = log (mode B) |
| 0x50 | ALPHA_Q12 | mean-mode threshold (mode A: 57313 = 14.0·4096) |
| 0x54/0x58 | LOG2ALPHA_Q26, GAMMA2_Q26 | log-mode terms (signed) |
| 0x5C | PFLOOR_K[31:16], PFLOOR_SH[4:0] | p_floor = max·k>>sh |
| 0x60/0x64 | DR_Q16, DX_Q16 | cluster report scaling |
| 0x80–0x94 | REP1–REP6 | report (below) |
| 0xA0–0xB4 | CNT_ADC/AVGGRP/RP/BS/MIG/DET | test-point beat counters |

**Report registers** (latched at `rep_done`, IRQ if enabled):

| Reg | Meaning |
|---|---|
| REP1 | total CFAR hits this frame |
| REP2 | number of clusters |
| REP3 | mean cluster depth, Q16 metres (Σ iz_peak·dr_q16 / nclust) |
| REP4 | mean cluster cross-range, Q16 metres |
| REP5 / REP6 | min / max cluster depth, Q16 metres |

Mode-A ready values for 0x10–0x64 are baked in `golden/regs_a.vh`
(mode B: `regs_b.vh`) — the PS driver can `#include` the same numbers the
regression uses.

## 4. Building for the ZCU208

Requires **Vivado 2023.2 or 2024.x** with ZCU208 board files.

```bash
# quick flat synthesis: utilisation + timing sanity (no BD, no bitstream)
vivado -mode batch -source fpga/scripts/vivado_build.tcl

# full block design (PS + RFDC + interconnect), bitstream + XSA
vivado -mode batch -source fpga/scripts/vivado_build.tcl -tclargs full
```

The script creates `fpga/vivado_prj/` (git-ignored) and writes reports to
`fpga/reports/`. The BD flow instantiates:

* `zynq_ultra_ps_e` — ZCU208 board preset, M_AXI_HPM0_FPD → AXI-Lite,
* `usmp_rf_data_converter` — ADC tile 224 conv 0: fs = 4.9152 GSPS
  (LMK04828 refclk 122.88 MHz), 4× decimation, **fine mixer NCO**;
  DAC tile 224 conv 0 mirrored (4× interpolation),
* `clk_wizard` — 245.76 MHz fabric clock (see caveat below),
* `gpr_top_zcu208` — module reference, `loopback` tied 0,
  `sb_req`/`sb_ack`/`irq` brought out for EMIO/GPIO mapping.

RFDC property names differ between IP versions; every property is applied
under `catch` and any failure is printed — configure the remainder in the GUI
against the table above.

**Clock caveat (honest):** 245.76 MHz cannot be produced from the 100 MHz
`pl_clk0` with integer MMCM ratios. Production setups feed the PL from the
ZCU208 on-board SI570 (PS-programmable over I²C — set it to 245.76 MHz and
constrain the PL differential pair in `zcu208.xdc`). The bring-up clk_wizard
lands at ≈245.83 MHz (+0.03 %); if you keep a non-nominal rate permanently,
regenerate the golden ROMs with the matching `F_CLK` in `make_golden.m`.

**RFDC data alignment:** `gpr_avg` coherently integrates *all* beats it
receives per tone (dwell × n_avg). For correct absolute scaling the RFDC fine
NCO must tune each tone (or the tone's sub-band center, with the residual IF
absorbed by the DDS/`fw` plan) so the beats inside a dwell are baseband-
aligned. The sub-band-major tone order and `sb_req/sb_ack` handshake exist for
exactly this PS retune loop.

## 5. PS software flow (Vitis / PetaLinux)

1. Load `gpr_zcu208.xsa`; build FSBL/PMUFW/ATF + U-Boot; boot.
2. `XRFdc_Init` → per sub-band: `XRFdc_SetMixerSettings` (fine NCO = sub-band
   center), `XRFdc_SetDecimationFactor`/`Interpolation`, `XRFdc_DynamicPLLConfig`
   if retuning tile clocks; acknowledge each `sb_req` with `sb_ack`
   (EMIO GPIO or polling).
3. Program 0x10–0x64 from `regs_a.vh` / `regs_b.vh` values (or the MATLAB
   `gpr_check_config`-derived table), set 0x0C = 0x2 (IRQ enable).
4. Write 0x04 = 0x1 (`run`). The chain acquires one frame (N_POS positions),
   streams through to the cluster and raises `irq` at `rep_done`.
5. Read REP1–REP6 (0x80–0x94), optionally the CNT_* test points (0xA0–0xB4)
   and STATUS (0x08: `bg_overrun`, `frame_count`); W1C 0x0C bit0.
6. For continuous operation re-write 0x04 = 0x1 per frame (`run` is one-shot
   by design — `frame_done` latches after N_POS positions).

**Lab bring-up without RF:** write CTRL with bit1 (`loop_mode`) and drive the
top-level `loopback` input high — the DDS output feeds `adc_if` directly
(exactly what `tb_chain` exercises: constant loopback ⇒ median removes
everything ⇒ REP1 = REP2 = 0 with all counters exact).

## 6. ROM loading

Simulation loads ROMs via `$readmemh` from `fpga/golden/` (copied into
`fpga/sim/` by `run_sims.sh`; small-parameter `*_t.hex` variants already live
in `sim/`). For synthesis, Vivado honours `$readmemh` initialisation when the
hex files are on the include path — add `fpga/golden` via
`set_property verilog_define`/`-sv_root` or simply keep the files next to the
run directory; alternatively let the PS push the same tables through AXI-Lite
where a register exists (all per-tone ROMs: fw, tidx, amp, sb_ends, cal, win,
twid, exp/log LUTs are generated by `make_golden.m` and are part of the repo).

All golden files are **pure integer hex** — no floating point text (Icarus
`$fscanf`/`$readmemh` compatibility).

## 7. Fixed-point conventions

| Quantity | Format |
|---|---|
| Stream I/Q data | Q15 signed, saturating |
| Calibration ROM | Q14 complex |
| DDS phase / CORDIC z | Q0.32 turns |
| CORDIC gain K | Q24 (10188014) |
| FFT gain | Q10 (18872 for 2048-pt mode A) |
| Migration geometry fb/roff/dx/dr | Q20 |
| Migration accumulator | 64-bit MAC → `>>>25` → sat26 → Q15 |
| exp LUT index | u_q20 `>>13`, 1024 entries |
| CFAR α (mean) | Q12 (57313 = 14.0·4096) |
| CFAR log-mode terms | Q26 signed (γ, log2α), reciprocal LUT icrom >> 30 |
| p_floor | max·2874 >> 28 |
| Cluster report depths | bin index × dr_q16 / dx_q16 → Q16 metres |

## 8. Known limitations / integration TODOs

* The RFDC BD configuration in `vivado_build.tcl` is a documented starting
  point; tile/slice/refclk choices must be matched to the actual ZCU208
  clock tree (LMK04828/SI5328) and validated with `validate_bd_design`.
* Single RX channel (1 ADC / 1 DAC). The MATLAB B12 8-port extension is not
  yet mapped to multiple RFDC slices.
* `sb_req/sb_ack` retune latency is PS-bound; at 50 µs dwell the mixer retune
  must stay within one sub-band boundary budget (21 sub-bands in mode A).
* No PL-DDR4 usage yet — all frame buffers fit in BRAM/URAM at mode-A sizes
  (64×2048 pipeline); larger frames would need a DDR MIG path in
  `gpr_background`/`gpr_cfar`.
